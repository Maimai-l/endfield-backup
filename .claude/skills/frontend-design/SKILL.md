# 前端设计规则

## 1. 真实性高于一切

- 视觉的来源只有《明日方舟：终末地》官网（源站 CSS 与素材包 `uploads/endfield-controls-pack/`）和游戏系统界面。色值、字体、尺寸、纹理、图标、动效的时长与曲线一律取自来源。
- 来源中已有的元素直接使用，不重新设计，不用近似物替代。
- 字体只用来源字体：SansRegular、SansMedium、SansBold、Novecento Sans Wide、Gilroy、Space Grotesk。不提出替换字体，不以授权、体积、可获得性或开源为理由建议替代品。
- 来源中没有、而工作界面必需的部分，从来源已有的形状、颜色、比例和动作推出，并在设计系统中标为“新增”。
- 任何建议与来源冲突时，不提出该建议。本规则与其他规则冲突时，以本规则为准。
- 简洁本身就是风格。品牌黄、施工警示式的配色与条纹不是风格来源，不为显得有风格而添加颜色、图标或纹理。

## 2. 界面中不出现注释类文字

渲染出来的界面只包含产品自身的内容。以下文字一律不出现在界面上：

- 注释，以及说明界面如何实现、为何如此设计的文字。
- 使用说明、规范条文、规格数值、对来源的引用。
- 对前端设计或实现要求的复述，例如“不使用圆点”“深色为默认”“品牌黄只作点缀”。
- 用风格词或设计术语充当标题与标签，例如“工业感”“白底墨字”“控件规范”。
- 占位说明，例如“示例”“此处放置”“待补充”。

界面上的文字来自业务本身：按钮写动作，标题写内容，英文标签是中文标题的直译。

文档同样不写元信息：不写生成过程、迁移记录、“未收录”或“未同步”清单、版本说明，也不写对文档自身的说明。

## 3. 排版

- 先定层级：每屏只有一个最大标题，其余逐级减小。相邻两级字号至少相差 1.5 倍；做不到时，字重和颜色必须同时拉开。
- 一屏最多使用 4 个字号，取自 tokens 中的 `fs-*`。
- 一律左对齐，正文不居中。所有元素对齐到共用的列线、文字边或基线。
- 字体分工照源站：中文用 Sans；英文标签、英文名，以及编号、快捷键、计数这类字母与数字混排的短文本用 Gilroy；纯数字的读数、页码、序号、百分比、日期用 Novecento Medium，等宽，可以放大作为一屏的视觉主体；全大写英文大标题与镂空装饰字用 Novecento DemiBold 或 Bold。
- Novecento 的数字与小写字母只有小型大写字母的高度，只有大写字母是全高，所以一段 Novecento 文字只排纯数字或纯大写字母，二者不混排。
- 英文标签全大写，字距 0.12em，放在中文标题上方。
- 分组靠留白和 1px 分隔线，不用多层边框，也不嵌套卡片。
- 同一行只放一个层级的信息，说明文字不与标题并排。
- 控件内的文字按字形墨迹垂直居中，与控件中心相差不超过 0.5px；带图标时文字与图标的中心对齐。交付前放大截图测量：纯数字与纯大写按真实字形测，大小写混排的英文按大写字母高度测。

## 4. 颜色与形状

细则见 `design-system/project/README.md`，以下几条不得违反：

- 颜色只用 tokens 中的值：来源色值，加上提醒角标橙 `#fb7803`、错误红 `#d2575e` 与警告珊瑚色 `#e8806e`。不用渐变，不用浅黄衬底。
- 品牌黄只作小面积点缀。
- 粉 `#ff1aac` 与青 `#00ffa2` 只出现在装饰色条中，不用于任何功能色、控件、文字、边框与底色。
- 不用任何形式的警示条纹。
- 状态只用文字与左侧色条表示，不画状态图标。
- 文字旁不加圆点；不用 unicode 箭头、符号或字符分隔符，并列内容用中文表述，例如“70 至 90”。
- 官网来源的按钮、标签、卡片、对话框用直角；游戏界面来源的确认按钮、实底胶囊按钮、胶囊标签与实底圆形按钮用全圆角（PillButton），同一面板内两套按钮不并排；用户输入与选择的控件用圆角。方形与圆形不做等大贴齐。
- 尺寸、间距与位置取 4 的倍数。

## 5. 动效与 token

- 动效的时长与曲线照源站对应控件的写法；源站本身不统一的地方不做统一。
- 新增控件取最接近的源站控件的写法；找不到对应控件时用 `ease`。不用回弹。
- 每个动效只有一个确定的时长和曲线；token 不提供可选项、预设或变体。
- 尊重系统的减少动效设置。

## 6. 交付前检查

- 深色与浅色两种主题都截图看过，深色为默认。
- 逐条对照以上规则，没有违反项。
- 没有为后续处理而有意保留的问题。
